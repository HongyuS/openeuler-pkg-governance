设计目标

基于公开 API，获取 openEuler 最新 LTS 与 最新创新版 的可选流（含全部 DevStation RC/每日构建）的全量软件包信息；与 Ubuntu（LTS + 前沿）逐包对比，标记哪些包过旧；标记核心包（P0/P1/P2）；标记长期未更新、无人维护（应日落）的包；在交互式界面中完成生态兼容性治理。

四大治理维度（对应 PPT）

  1. 月度活跃度：近 1/3/6/12 月滚动加权 → A/B/C/D；仓库待办（未闭环 Issue/PR）。
  2. AI 全量包画像：活跃度 × 重要性 × 关键包（Python 依赖闭包）→ 核心/重要/普通 + P0/P1/P2。
  3. 人力估算：人日/包 = 升级 + CVE 修复 + 例行维护 → 汇总团队容量。
  4. 交互式输出：逐包画像、多维筛选排序、版本对比列、特殊包标识、活跃度趋势。

分层更新波次

P0 最小关键集合（kernel/glibc/openssl/systemd/python+闭包）优先对齐最新 release； P1 网络/存储/工具链；P2 上层应用最后。

可选的创新 / LTS 流

页面顶部可切换：LTS 展示当前维护的全部 LTS（如 24.03 LTS、SP1–SP4）；创新版 展示已发行创新版（24.09/25.03/25.09）与 26.09-DevStation 的全部 RC / 每日构建，切换后版本列与“落后基线”实时重算。

默认源聚合

同一 src-openeuler 包的二进制最新版可能在 update，源码在 source/update-source， 调试符号在 debuginfo，扩展在 EPOL/main，基础在 OS。采集按源聚合， version 取 /OS / everything / EPOL / update 的最新，并标记 has_source/has_debug/in_epol/in_update。

Python/pip 包治理

python-* 分为 系统 Python 运行时（python3*/libpython，P0 不日落）与 pip 模块（对应 PyPI 上游）。对 pip 模块采集 PyPI 画像：上游是否停更（>730 天）、 Requires-Python 是否被系统 Python 满足（不满足即“Python 版本屏障”）、反向依赖压力； 仅在 PyPI 停更 + 无反向依赖 + 非核心 时建议日落，其余给出明确处置提示。

运行

make install
make build        # 实时全量采集（含多流版本矩阵）
make run          # http://127.0.0.1:8000
